# カレンダー共有アプリ 要件書

## プロジェクト概要
家族・グループ向けのカレンダー共有アプリ。複数のカレンダーをグループ内で共有し、共同でスケジュール管理を行うことを目的とする。

## ユーザーストーリー

### US-1: 新規登録
- ユーザーはメールアドレスとパスワードで登録できる
- 登録後は自動的にオンボーディング画面（`/onboarding`）に遷移

### US-2: グループの作成
- ユーザーは新しいグループを作成できる
- グループ作成時に招待リンクが自動生成される
- 1ユーザーが複数のグループに所属可能

### US-3: グループへの参加
- 招待リンク（`/join/:token`）で誰でも参加可能
- セキュリティ制限なし

### US-4: カレンダーの利用
- カレンダーはグループ参加時に「プライベート」が自動作成される
- グループ内全員がすべてのカレンダーを閲覧可能
- 画面設計では「プライベート」「仕事用」の2タブを固定提供

### US-7: 仕事用カレンダー・シフト管理
- 仕事用カレンダーでグループ全員のシフトを月表示で確認できる
- 各ユーザーは自分のシフトパターン（名称・色・勤務時間・休日フラグ）を管理できる
- シフトパターンを日付に割り当てることで自分のシフトを登録できる
- 他のメンバーのシフトは閲覧のみ（編集不可）

### US-5: イベントの作成・編集
- ユーザーはカレンダー内にイベントを作成
- イベント編集・削除は作成者のみ
- 他のメンバーは閲覧のみ

### US-6: イベント情報の表示
- イベント一覧を月単位で表示
- イベント情報：タイトル・日時・場所・メモ・色

## 機能要件

### 認証
- **メール認証**: メールアドレス＋パスワード（Supabase Auth）
- **ログイン / ログアウト**: 標準的な認証フロー

### グループ・ユーザー管理
- 1ユーザーが複数グループに所属可能（同一グループへの重複参加は不可）
- 招待リンク経由の参加（セキュリティ制限なし）
- グループ未所属のユーザーはカレンダー・イベント・シフトを閲覧不可（403）
- グループ内全員が同じカレンダーセットを閲覧可能
- 設定画面でグループを切り替え可能（複数グループ所属時）。切替えた状態はlocalStorageで永続化

### メンバー管理
- 設定画面のメンバー一覧からメンバー詳細モーダルを開ける
- メンバー詳細モーダルにはアバター・表示名・メールアドレス・メモを表示
- メモ（最大200文字）は自分のプロフィールのみ編集可能。他メンバーのメモは閲覧のみ
- メモの保存は `PATCH /users/me` で行い、グループ内の全メンバーに反映される
- **グループ退会権限**: 本人（ただしグループオーナー自身を除く）またはグループオーナーのみ退会操作が可能
- 退会フロー: 詳細画面 → 退会確認画面 → `confirm()` ダイアログ → API 実行
- グループオーナーは自分自身をグループから退会させることはできない
- 退会後も招待リンクから再参加可能（GroupMember レコードの削除のみ。User は残る）

### カレンダー
- カレンダーはグループ参加時に自動作成（ユーザーによる作成・削除は対象外）
- カレンダーのON/OFF切り替えはクライアント側の状態管理（DBカラム不要）

### シフト管理
- シフトパターン（名称・色・開始時間・終了時間・休憩・休日フラグ）をユーザーが自由に作成
- 日付ごとに自分のシフトパターンを割り当て可能
- グループメンバー全員のシフトを仕事用カレンダーで確認可能

### イベント管理
| 項目 | 内容 |
|------|------|
| **タイトル** | 必須 |
| **日時** | 終日 or 時間指定（両対応） |
| **メモ** | 任意 |
| **色** | 任意（プリセットカラーから選択） |
| **編集権限** | 作成者のみ編集・削除可能 |
| **閲覧** | 認証済みユーザー全員が閲覧可能（グループ外も含む） |
| **グループ紐付け** | イベントは `calendarId` からカレンダーを逆引きし、そのカレンダーの `groupId` に紐づく。フロントは選択中のグループIDをクエリパラメータとして `/events/new?groupId=xxx` で渡し、そのグループのカレンダーを使用する |

### 通知・リアルタイム
- **リアルタイム同期**: 不要（画面更新で十分）
- **通知**: なし

## UIデザイン要件

- **参考アプリ**: LifeBear
- **ビジュアル**: 色分けされたイベントバッジ、複数カレンダーの重ね表示
- **レイアウト**: 月表示メイン、シンプルな縦長デザイン
- **マルチタブUI**: ToDo・ノートなども将来的に統合可能な構造

## ユーザーセッション

### セッション1: ログイン前
1. ランディングページ
2. 新規登録 / ログイン

### セッション2: ログイン後（グループ未参加）
1. グループ作成ページ
   - グループ作成 → 招待リンク生成
   - または、招待リンク入力で参加

### セッション3: グループ参加後
1. カレンダー選択画面
2. 月別カレンダー表示（複数カレンダーの重ね表示）
3. イベント追加・編集・削除

## 制約・非機能要件

| 項目 | 内容 |
|------|------|
| **プラットフォーム** | Web のみ |
| **ブラウザ互換性** | 最新版Chrome/Firefox/Safari |
| **レスポンス時間** | API 応答時間 < 200ms |
| **スケーラビリティ** | 初期段階は小規模（100ユーザー程度）対応 |
| **データ保持** | 無期限（削除手段は後日検討） |

## 開発フロー

### ブランチ戦略

| ブランチ | 用途 |
|---------|------|
| `main` | 初期ブランチ |
| `develop` | 開発用ブランチ |
| `release` | リリース用ブランチ |

- PRのマージ先は常に `develop` ブランチとする

### CI/CD

環境は **開発環境** と **本番環境** の2つのみ（ステージング環境なし）。

| ワークフロー | トリガー | 内容 |
|------------|---------|------|
| CI | PR → `develop` / `release` | lint・型チェック・ビルド |
| Deploy Development | push → `develop` | Vercel preview + Render dev デプロイ |
| Deploy Production | push → `release` | Vercel production + Render production デプロイ |
